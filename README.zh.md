# dsh-session-quickbar

中文 | [English](README.md)

每个会话行右侧那排快捷按钮现在有唯一的主人：按会话决定显示哪些按钮、按什么顺序，并让制作插件的会话与这排按钮之间建立双向交流。

## 做什么

- **接管这一排。** 快捷栏注册在 `sidebar.workspaces.session.row.action`；接管模式（默认开启）下，只要快捷栏在渲染，就会隐藏同一槽位里的其他条目。你配置什么，行里就显示什么，而不是各插件注册顺序碰巧排出来的样子。
- **内置按钮复用现有数据。** 星标读写会话星标插件的 `/session-stars` 路由；待办方格读写 `/session-todos`；置顶、归档走公开的 `uiWorkspace` 服务（会话还在跑时会弹出同样的“停止并归档”确认）。复制 ID 默认隐藏，可随时打开。
- **按会话配置。** 一套全局默认，加上每个会话的独立覆盖。隐藏的按钮保留位置，可随时重新打开；顺序用上移/下移调整。
- **侧栏入口可定制。** 设置页列出左侧栏的面板入口；取消勾选即从列表收进宿主的「更多」菜单，仍然一键可达，选择保存在 `session-quickbar.json`，刷新后保持。
- **插件清单。** 设置页会列出 profile 里带浏览器半边、已安装的插件，并标成 **已内置 / 已登记 / 可接入 / 未启用**，一眼看出还有哪些插件该接入快捷栏。`session_quickbar action=plugins` 把同一份清单给到会话。
- **真正的设置页。** 左侧面板列表里的 **快捷栏**，或任意会话行菜单里的 **快捷栏设置…**。页面可编辑全局布局或单个会话布局，显示每个按钮的来源，并列出通道的订阅会话与最近消息。
- **处处实时。** 布局变更通过 Server-Sent Events 推送到每个打开的窗口，不用刷新。
- **面向插件制作会话的双向通道。** `session_quickbar`（宿主工具）让任何会话读写布局、登记自己正在做的按钮、订阅变更、给别的会话发消息。每次布局变更都会以一条短消息注入订阅的会话；登记归属的会话还会收到“你的按钮现在在第几位/被隐藏”。对方用 `notify` 回信，于是快捷栏和维护它的会话可以双向沟通。

## 在哪里

```
侧边栏会话行（悬停时）
┌──────────────────────────────────────────────────────────────┐
│ ● 会话标题                                 …   ★  ☑  ▣  📌  │
└──────────────────────────────────────────────────────────────┘
   快捷栏，顺序来自设置页
```

设置页：左侧面板列表 → **快捷栏**，或会话行菜单 → **快捷栏设置…**。

## 配置

- **全局默认** —— 所有会话继承的布局，以及“接管这一排动作”开关。
- **单个会话** —— 选一个会话，只调整这一行；**改用全局布局** 会删除覆盖。
- **恢复默认** —— 清空显式布局，回到内置默认（待办 + 完成提醒两个按钮）。

布局文件是 `$DSH_HOME/session-quickbar.json`，删掉即恢复默认。关闭插件后快捷栏消失，星标与待办插件自己的按钮照常显示。

## 接管模式改变了什么

快捷栏在渲染且接管开启时，一条 CSS 规则会隐藏同一槽位里的其他条目——包括宿主自带的归档、置顶，由快捷栏自己重画。如果快捷栏因故没有渲染（或插件被禁用），规则不生效，原有按钮自动回来。设置页里关闭接管，可以同时保留两套按钮（迁移过渡期有用）。

## 其他插件如何登记按钮

任何客户端插件都能贡献按钮，不必改这个包：

```js
const dispose = window.dshSessionQuickbar.register({
  id: 'my-button',
  owner: 'my-plugin',         // 可选包名，清单里会显示“已登记”
  labels: { zh: '我的按钮', en: 'My button' },
  hint: { zh: '一句话说明', en: 'One-line hint' },
  order: 120,
  icon: 'M3 8h10',            // 16×16 的 path，设置 Component 时可省略
  isActive: (sessionId) => false,
  onActivate: (sessionId) => { /* … */ },
  subscribe: (listener) => { /* isActive 变化时通知 listener */ return () => {} },
})
```

插件卸载时调用 `dispose()`。`star`、`todo`、`archive`、`pin`、`copy-id` 是保留 id。也可以提供 `Component`（`({ sessionId }) => …`）代替 `onActivate`。登记会同步到宿主注册表，`session_quickbar` 工具和设置页都能看到。

完整契约（含宿主工具与“已有行按钮的插件如何迁移”）见 [CONTRACT.md](CONTRACT.md)。

## 限制

- 只管这一排；其他行、行菜单、会话页头部不受影响。
- 快捷栏不能调用别的插件的 React 代码，只能通过注册表；未迁移插件的按钮是被接管隐藏，而不是被吸收。
- 通道目标支持精确会话 id、精确标题、唯一标题片段。标题由浏览器端在设置页打开时上报；没上报过就传精确 id。
- 目标会话没加载时，消息排队，等它启动后按顺序注入，并用最后一条显式消息唤醒一次，所以请求会出现在它的对话里。设置页「会话通道 → 待投递」能看到队列，排队中的会话行带一个琥珀色计数；`notify` 对已加载的空闲会话默认也会唤醒（`wake: false` 只静默排队），布局变更通知从不唤醒。
- 触屏布局沿用宿主规则：只保留置顶按钮，快捷栏同样遵循。
